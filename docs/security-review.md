# RC1 security review and threat model

Review the immutable RC commit and exact signed artifacts. Primary assets are user identities and sessions, provider credentials, encryption and signing keys, agent secrets, infrastructure inventory, lifecycle task integrity, audit history, backups, and release artifacts. Trust boundaries include browsers and the TLS proxy, API and worker, PostgreSQL, RabbitMQ, provider APIs, Workstation Agents, secret/KMS services, backup storage, signing services, registries, and observability systems.

Required abuse cases include credential theft, login guessing, CSRF and session fixation, RBAC bypass, request smuggling and oversized bodies, SSRF through provider endpoints, provider error leakage, command replay, agent impersonation, malicious or rolled-back upgrades, queue replay, duplicate lifecycle operations, database or broker interruption, ciphertext/key substitution, backup tampering, log injection, supply-chain compromise, and administrative misuse. Confirm the existing controls and test their failure modes rather than accepting documentation alone.

Run the approved SAST, dependency, container, malware, and repository-secret scanners against the immutable commit and artifacts. `node tools/scan-repository-secrets.js` provides a narrow repository safety check and reports only rule, file, and line—never matched secret text. It supplements, but does not replace, the approved enterprise scanner. Review provider service-account permissions against least privilege and confirm staging accounts cannot affect production.

Perform authenticated and unauthenticated API testing, browser security testing, RBAC role testing, agent protocol and upgrade testing, cryptographic configuration review, backup recovery security review, and logging/redaction inspection. Penetration testing must include safe abuse-rate validation and must not target production. High and critical findings must be remediated before approval; remaining low or informational findings require an owner, due date, and tracking reference.

Complete `deploy/security-review-evidence.example.json` and evaluate it with `node tools/evaluate-security-review.js <evidence.json> [report.json]`. Evidence must identify an independent reviewer, approval reference, retained sanitized evidence, and the immutable source revision. Evidence older than fourteen days is rejected.
