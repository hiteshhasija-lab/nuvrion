# Production operations

Use `deploy/compose.production.yaml` with `NUVRION_IMAGE`, `NUVRION_POSTGRES_IMAGE`, and `NUVRION_RABBITMQ_IMAGE` set to approved immutable image digests; deployment fails if any are absent. Store `.env.production` with owner-only permissions outside source control and inject its values from the deployment secret manager. Terminate TLS at a hardened reverse proxy; the application port binds to loopback by default, and PostgreSQL and RabbitMQ remain on an internal network with no host ports.

Before promotion, apply all migrations, validate production configuration, complete the release-qualification runbook, verify a recent recoverable backup, and require `/api/v1/readiness` to return `ready`. `/api/v1/health` is a liveness and diagnostic view. Authorized platform administrators can retrieve cumulative Prometheus text from `/api/v1/platform/metrics/prometheus`; configure the collector with a least-privilege authenticated session, scrape over TLS, and never expose this route publicly.

Alert when readiness is unavailable for two consecutive checks, HTTP 5xx rate exceeds 1%, task queue depth grows for five minutes, any task enters `verification_required`, unpublished outbox messages increase, an agent becomes offline, or backup verification fails. Correlate structured logs using `correlationId`; restrict log access and retention because infrastructure identifiers may be operationally sensitive.

For shutdown, remove the instance from traffic and allow at least the configured 45-second grace period. The API stops accepting connections, closes maintenance and relay loops, drains the worker, and then closes persistent state. Do not force termination while tasks are running unless recovery procedures are active. Scale workers gradually, verify broker and database capacity, and preserve idempotency guarantees. Use the backup/restore runbook for recovery and reconcile every `verification_required` task before normal operation resumes.
